# GUI local da Bancada — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Consultar e comparar runs existentes pelo navegador sem alterar o SQLite ou chamar modelos.

**Architecture:** Leitor SQLite independente do store mutável, métricas puras e aplicação Flask com HTML/CSS/JavaScript locais. A CLI importa a GUI sob demanda. O histórico lê resultados somente da página selecionada.

**Tech Stack:** Python >=3.10, SQLite, Pydantic existente, Flask >=3.0,<4, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-10-05-gui-local-design.md`

## Global Constraints

- Servidor somente em `127.0.0.1`, porta default `8765`, sem debug/reloader/opção de host.
- Extra opcional `gui`; instalação `pip install -e '.[dev,gui]'`; nenhuma dependência Node/CDN.
- Banco em URI `mode=ro`; não chamar `_connect()` do store, criar bancos ou migrar schema.
- Histórico paginado em 25 runs; filtros persistidos na URL.
- Conteúdo do modelo exibido como texto escapado; GUI não executa inferência ou código gerado.
- Preservar 53 casos manuais, 12 HumanEval e até 70 chamadas; não iniciar llama-server.
- Commit de retorno: `48203b0edbfe6657eb6f881cfa3c02777eeb20f6`.
- Trabalhar no checkout existente `/workspace/IAA`; não criar outro worktree sem pedido do usuário.
- Implementação por workers `gpt-6-luna` (high; max quando necessário); revisão e julgamento sempre por Sol, medium nas tarefas simples.

## Review Focus

- Caminhos com espaços, `?` e `#`: abrir o arquivo correto, sem interpretar sua grafia como opções URI (Task 1).
- Run/payload antigo ou inválido: informar ausência/erro, sem migrar ou contar como aprovado (Task 1).
- Métricas nulas, não finitas ou julgamento parcial: não produzir médias inventadas ou gráficos inválidos (Task 2).
- Runs com listas distintas/IDs repetidos: impedir comparação enganosa e manter denominadores visíveis (Task 2).
- Extra GUI ausente e distribuição instalada fora do checkout: CLI base funciona e recursos da GUI são empacotados (Tasks 3/4).

### Task 1: Leitura somente leitura e compatibilidade

Erros de arquivo/schema são `DatabaseReadError`; erro de payload pertence à entrada, não some silenciosamente.

- [ ] Escrever `test_read_page_does_not_modify_database` com duas entradas via `save_run`, comparação dos bytes e schema antes/depois; `assert read_page(db).total == 2`. Provar filtro/paginação com 26 runs, ordenação timestamp/ID e `len(page.entries) == 25`.
- [ ] Escrever `test_missing_database_is_not_created`, `test_legacy_columns_are_not_added`, `test_corrupt_payload_is_visible` e `test_database_path_uri_characters`. Assertivas: arquivo ausente continua ausente; schema legado permanece igual; entrada inválida contém `error` e `run is None`; caminho `runs ?#.sqlite` abre corretamente. Schema obrigatório sem tabelas esperadas gera `DatabaseReadError`; tabela de juiz ausente equivale a julgamento indisponível.
- [ ] Executar `python -m pytest tests/test_gui_reader.py -v`: falha por módulo ausente, não por fixture inválida.
- [ ] Implementar contratos usando `Path.resolve().as_uri()`, conexão `mode=ro`, colunas opcionais detectadas por PRAGMA, consultas parametrizadas e conexão fechada por operação. Filtrar metadados sem carregar payloads de todas as páginas; entradas inválidas ficam explicitamente indicadas. Aceitar defaults históricos dos modelos; não importar funções mutáveis do store.
- [ ] Executar o arquivo de testes e `ruff check src/bancada/gui tests/test_gui_reader.py tests/gui_helpers.py`; todos passam. Commit `feat: add read-only SQLite reader for local GUI`.

### Task 2: Estatísticas e comparação corretas

**Files:** `metrics.py`; `tests/test_gui_metrics.py`.

**Interfaces:** `case_passed(result: CaseResult) -> bool`; `run_metrics(run: Run) -> dict[str, Any]`; `compare_runs(a: Run, b: Run) -> dict[str, Any]`. Consome `Run` do leitor. Resumo produz `total`, `passed`, `machine_rate`, `enem`, `categories`, `difficulties`, `fail_reasons`, `judge_mean`, `judge_count`, `tps_p50`, `tps_count`, `latency_p50_ms`, `latency_p95_ms`, `time_sum_ms`, contagens/somas de tokens e processamento de prompt. Denominadores explícitos; rate/médias sem amostra são `None`. P95 usa interpolação linear sobre valores ordenados.

- [ ] Escrever `test_missing_metrics_and_partial_judge` com dois casos, um único score=3 e uma única velocidade=30: `judge_mean == 3`, `judge_count == 1`, `tps_p50 == 30`, `tps_count == 1`. Sem medidas, médias são `None`; excluir números não finitos e scores inválidos, preservar score zero e auto flag por caso.
- [ ] Escrever `test_comparison_only_scores_common_cases`: A contém IDs x/y, B x/z; `common_total == 1`, `only_a == ['y']`, `only_b == ['z']`; mudança em x classificada como regressão/melhoria conforme checks. `test_comparison_warns_on_config_difference` verifica seed/versões/limites ausentes ou diferentes, versão importada histórica ambígua; modelo diferente não é incompatibilidade por si só. IDs duplicados produzem erro de dados, sem sobrescrever um resultado silenciosamente.
- [ ] Executar `python -m pytest tests/test_gui_metrics.py -v`, confirmar falha pelas funções ausentes.
- [ ] Implementar funções puras reutilizando `summarize_run`; checks vazios/erro não passam. Campos novos de turno são lidos quando presentes, sem exigir correção da bateria como pré-requisito. Comparação retorna `rows`, `common_total`, `common_pass_a`, `common_pass_b`, `only_a`, `only_b`, `warnings`. Velocidade de dois turnos e tempo acumulado mantêm os rótulos definidos na spec.
- [ ] Executar testes e ruff; commit `feat: calculate GUI statistics and aligned run comparisons`.

### Task 3: GUI, recursos e comando local
